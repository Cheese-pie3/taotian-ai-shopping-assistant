# 帮我凑对｜面试讲解稿

## 1. 项目背景

大促期间，用户经常遇到三个问题：

- 优惠规则复杂，不知道哪些券已经生效。
- 不确定凑单后是否真的更便宜。
- 担心现在买之后又降价。

所以我设计了一个购物车 AI 下单陪跑助手，帮助用户在下单前做决策。

## 2. 产品定位

它不是替用户盲目找低价，而是帮用户完成一条可解释链路：

```text
购物车诊断 -> 优惠检查 -> 凑单判断 -> 买/等决策 -> 价保提醒
```

核心原则是：先算清楚，再解释，再给下一步。

## 3. Demo 说明

当前 Demo 使用模拟购物车、模拟优惠规则和模板化 AI 回复。

它不接入真实淘宝/京东 API，也不声称识别所有隐藏券、直播券或真实历史价格。它主要验证产品流程、交互方式和解释逻辑。

## 4. 真实落地依赖

如果在真实平台落地，需要接入：

- 购物车数据
- 营销活动和券数据
- 用户权益和已领券状态
- 会场券、直播券、会员券数据
- 价格历史和加购价格
- 订单与价保 API

## 5. 指标设计

可观察指标包括：

- 凑单建议点击率
- 凑单建议采纳率
- 优惠使用率
- 下单转化率
- 价保提醒开启率
- 用户对解释的满意度
- 不必要凑单减少率

## 6. 面试总结表达

我认为这个项目的重点不是证明 Demo 已经能上线，而是展示我如何把一个复杂大促决策问题拆成清晰的产品链路，并用 AI 解释层降低用户理解成本。
